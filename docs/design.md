# 설치형 시험판 설계

## 목표와 실행 순서

윈도우 프로그램은 로컬 대시보드를 열고, 픽셀 앱은 선택한 Wi-Fi 또는 USB 연결을 통해 영상을 받는다. 둘은 같은 전송 프로토콜을 사용한다. 픽셀의 구글 포토 앱이 클라우드에 업로드한다. Windows 실행 파일과 Android 10용 시험 APK를 제공한다.

1. PC에 원본 폴더 경로와 설정을 등록한다. 원본은 읽기 전용으로 연다. PC는 경로, 확장자, 크기, 수정 시각과 파일 ID를 기록한다.
2. 픽셀에서 PC와 페어링한다. PC가 생성한 HTTPS 인증서 지문과 전송 토큰을 사용한다. Google 계정 비밀번호나 API 키를 받지 않는다. USB는 승인된 데이터 케이블 연결에서 ADB 역방향 포트 전달을 사용한다.
3. PC는 설정한 묶음 용량과 픽셀이 보낼 여유 공간으로 묶음을 만든다. 기본값은 50GB이며, 여유 공간 설정과 영상별 한도가 적용된다. 감당할 수 없는 파일은 이유를 표시하고 대기한다.
4. 픽셀은 MediaStore에서 자기가 만든 항목을 전송 중 비공개로 유지한다. HTTP Range로 끊긴 지점부터 받는다. 받은 파일의 SHA-256이 PC와 일치한 뒤 공개한다.
5. 구글 포토 전용 폴더 백업을 처음 한 번 켠다. 픽셀의 접근성 서비스는 포토의 활성 화면에서 기대 계정, 영상 이름, 백업됨, 원본 화질을 확인한다. 시험판에서 확인에 필요한 화면을 열 수 있다. 실기기에서 노출이 확인되지 않은 화면은 판정 보류로 처리한다.
6. PC는 파일별 전송·검증·정리 상태를 보관한다. 묶음 전체가 검증된 뒤에만 정리를 허용한다. 기본값은 PC에서 명시적으로 정리 승인이다. 자동 정리를 켜도 같은 검증이 적용된다.
7. 픽셀은 정리 허용을 받은 묶음에서, 자신이 생성했다고 기록된 미디어 ID만 삭제한다. 묶음이 비워진 뒤 다음 묶음으로 넘어간다.

## 예약·재개·진행 보고

- PC가 상태 변경을 저장한 뒤 다음 지시를 보낸다. 픽셀은 미디어 ID와 전송 및 검증 상태를 저장한 뒤 보고한다.
- 전화의 진행 보고에는 현재 파일, 전송 바이트 수, 확인한 파일 수, 배터리, 잠금 상태가 포함된다. PC는 검증 결과를 파일 ID로 집계한다. 상태가 바뀌면 즉시 보고하고 기본 주기는 15초다.
- 아직 화면에서 확인하지 못한 구글 포토 업로드의 퍼센트는 표시하지 않는다. 잠금 상태에서는 마지막 검증 시각과 진행률을 유지한다.
- 설정한 포토 계정의 백업 설정 화면에서 계정 확인이 필요하다. 계정 확인이 만료되면 다시 요청한다. 파일 이름, 백업 상태 또는 원본 화질이 불분명하면 확인을 완료하지 않는다.

## 포함할 검증

| 시험 | 성공 기준 |
| --- | --- |
| 파일 선택과 묶음 계산 | 지정 폴더 바깥의 파일과 미지원 항목을 전송하지 않는다. 파일 수와 용량이 중복 집계되지 않는다. |
| 전송 중 재연결 | Range 재개 후 원본과 SHA-256이 일치한다. |
| 자동 정리 | 미확인 파일이 있으면 정리 지시가 만들어지지 않는다. 저장되지 않은 미디어 ID는 건드리지 않는다. |
| 실기기 포토 | 픽셀 1의 백업 계정 및 영상별 세부정보를 읽는다. 미백업, 다른 파일, 절약 화질을 완료로 판정하지 않는다. |
| 소량 시범 작업 | 화면 잠금, Wi-Fi 중단, USB로 전환, 승인 후 정리까지 시험한다. 픽셀 8 프로에서 백업본을 재생한다. |

실기기 시범 작업 결과를 확인한 뒤 1~5GB, 50GB, 약 1TB 순서로 확대한다.
